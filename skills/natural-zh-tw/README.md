# 去 AI 味｜文章優化版

`natural-zh-tw` 用來把繁體中文文章改得自然、具體、容易閱讀，並加入依語義分段、段落留白與交稿核對。只需要安裝這一個資料夾；不需要再疊加其他 humanizer skill。

## 這一包含什麼

完整生成流程、品牌資料更新方式與 LINE 訊息範本，請看 [完整使用說明](references/writer-guide.md)；定稿差異與 CTA 核對規則見 [品牌與定稿回饋](references/brand-and-revision.md)。

- 去除空泛套話、誇大語氣與機械句型，保留作者觀點。
- 繁體中文、台灣用語與標點校正。
- 保留事實、數字、專名、SEO 關鍵字、引文、網址與承諾。
- 同一意思留在同一段，語義轉換才分段；段落間留白，不逐句換行。
- 按需提供完整的替換前／替換後對照表，以及文件交付核對。

本優化版以 Raymond Hou 採 MIT 授權發布的 `speak-human-tw` 為基礎，另行整合語義分段、SEO 二次確認、品牌資料與文件交付機制。分段設計參考 `seo-reading-experience` 的語義切段原則；Google Docs 工具只負責文件交付，沒有打包任何帳號、憑證或專用連接器。

## 安裝

從 GitHub 下載本儲存庫，將 `skills/natural-zh-tw` **整個資料夾**放進所用工具支援的 skills 目錄。必須保留 `SKILL.md` 與 `references/`，不要只複製單一檔案。

常見專案安裝位置為 Claude Code 的 `.claude/skills/natural-zh-tw/` 或 Codex 的 `.agents/skills/natural-zh-tw/`。依工具的載入方式重新開啟專案，確認可以選到 `natural-zh-tw`。不支援 skills 的聊天工具，可附上本包檔案作為編輯規範使用；這不等於已安裝原生 skill。

## 怎麼觸發

安裝完成後，只要在修改文章的需求中提到「說人話」「去 AI 味」或「去AI味」，就會觸發這個 skill。句子不必完全相同，例如：

- 幫我修改文章，說人話一點。
- 幫我修改文章，去 AI 味。
- 幫我把這篇文章去AI味，讀起來自然一點。

只提到「幫我修改文章」但沒有指定這些風格時，工具會依當下需求判斷；如果只是詢問「說人話」或「去 AI 味」的意思，也不會直接改稿。

## 建議使用流程

文章初稿完成後，可以先用這個 skill 做一次語句轉譯，再檢查 SEO 關鍵字是否仍自然保留在標題、H2、H3 與必要段落。口語潤飾有時會合併句子或改變關鍵字位置；如果因此影響原本的 SEO 規劃，再依搜尋意圖調整，避免為了保留關鍵字而讓句子變得生硬。

品牌介紹、CTA 或品牌經歷請以委託人指定的最新品牌資料為準。完成後再核對事實、數字、專名、連結與承諾，確認沒有在改寫時被改動。

## 直接貼到 Claude 或 Codex 的指令

```text
請使用 natural-zh-tw 處理以下文章。這次直接套用，不用先列清單等我確認。
保留事實、數字、品牌名、SEO 關鍵字、引文、CTA 與網址，不新增作者經歷或承諾。
去除空泛套話與誇大句型，調整成自然的台灣繁體中文。
依語義分段：同一個意思的幾句話留在同段，換論點再分段；段落間留白，不逐句換行。
如果我有提供 SEO 關鍵字，改寫後請再次確認它們是否仍自然出現在標題、H2、H3 與必要段落；若口語潤飾造成遺失或語意衝突，請調整到自然且符合搜尋意圖的位置。
交付完整改寫文章，最上方附「替換前／替換後」對照表；排版調整另以一句話說明。
需要我補資料的地方請明確標出，不要代編。

文章：
〔在此貼上原文〕
```

只要審閱時改用：「先標出問題與建議，不要改寫。」預設保留先審閱再套用的模式；上面的直接改寫指令會明確啟用事後摘要模式。

需要 Google Docs 可追加：「每篇另建一份 Google Doc，保留原始文件，放到我指定的資料夾；使用原生標題、表格、段落與超連結，完成後提供網址。」執行環境須先具備可用的 Google Docs 讀寫工具；本包不包含連接器。

## 排版結果怎麼看

同一段可以有兩三句，也可以只有一句，取決於意思是否完整。一般文字在段落間空一行；Google Docs 使用原生段落與段後間距。以讀者能清楚辨認段落為準，不限定每段句數，不用空段和大段距重複撐高。

本包保證的是可檢查的編輯規則，不保證不同模型逐字產出相同文章，也不保證任何偵測器分數。
